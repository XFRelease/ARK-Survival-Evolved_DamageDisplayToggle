第一章 · 软件总览

软件总览

「伤害显示开关（DamageDisplayToggle）」是一款方舟生存进化服务端 ArkApi 插件：玩家用两条聊天命令自助开关自己屏幕上的浮动伤害数字，设置按 SteamID 存入 SQLite 数据库，重启服务器不丢失。拦截发生在服务器下发通知的环节，只影响选择关闭的玩家本人，不改动任何伤害数值、不影响其他玩家。同时，浮动伤害数字由服务器实时生成并逐个下发，是大型战斗中一笔持续的服务器开销——玩家在不需要时关闭，即为服务器减负，人越多越明显。

🎚️

玩家自助开关

/开启伤害显示、/关闭伤害显示，玩家自己管理，无需服主介入。

🗄️

SQLite 持久化

按 SteamID 记忆开关状态，内置 SQLite 引擎，免安装数据库服务。

🎯

只影响本人

关闭后仅该玩家客户端收不到伤害数字，伤害数值与其他玩家完全不受影响。

💬

气泡通知配置驱动

所有提示文案、字号、时长、颜色集中在 config.json 的 Notification 节。

✏️

命令文本可改名

玩家命令文本在配置里改，Reload 热重载后自动按新文本重挂。

🔄

配置热重载

控制台 / RCON 执行 DamageDisplayToggle.Reload，免重启刷新配置。

第二章 · 环境要求

环境要求

项目要求
操作系统Windows（服务端为 Windows 版方舟生存进化服务器）
服务端插件框架ArkApi，最低版本 3.5（依据 Output/PluginInfo.json 的 MinApiVersion 字段）
数据库无需安装。插件内置 SQLite（源码直编），数据库自动落在插件目录下，无外部数据库服务依赖
编译环境（开发者）Visual Studio 2019 v142 或更高版本工具集、MSBuild；需先设置环境变量 ASE_API 指向 ServerAPI 目录（工程脚本 环境变量.bat 负责设置）
第三章 · 部署安装

部署安装

以下为拿到编译好的插件后在服务器上的部署步骤。插件英文名为 DamageDisplayToggle。

  1. 确认服务器已安装 ArkApi

    检查服务器目录 ShooterGame\Binaries\Win64\ArkApi\ 是否存在 → 存在则继续；不存在请先安装 ArkApi（最低 3.5）。

  2. 复制插件文件

    把 PluginInfo.json、config.json、DamageDisplayToggle.dll 复制到 ShooterGame\Binaries\Win64\ArkApi\Plugins\DamageDisplayToggle\ → 目录不存在时先创建（工程自带的 一键安装.bat 会自动完成复制与建目录）。

  3. 检查配置文件

    打开插件目录下的 config.json，确认内容为合法 JSON，且 Notification 节四个必需条目齐全 → 配置详解见第四章。

  4. 重启服务器

    启动方舟服务器 → 服务器控制台出现「先锋.伤害显示开关(1.0)」横幅日志即表示插件加载成功；首次加载会在插件目录自动创建数据库文件 DamageDisplayToggle.db。

  5. 验证命令

    游戏内聊天发送 /关闭伤害显示 → 屏幕弹出「已关闭伤害显示」气泡即一切正常；控制台 / RCON 执行 DamageDisplayToggle.Reload → 返回 Reloaded config 表示重载命令可用。

若 config.json 缺失、不是合法 JSON、或 Notification 节缺少必需条目（ReloadSuccess / ReloadFailed / ShowDamageOn / ShowDamageOff / SaveFailed），插件加载时会直接报错拒绝启动。这是「配置错误响亮失败」的设计：按报错信息补全配置即可。部署前务必确认配置文件完整。
编译产物位于工程 Output\DamageDisplayToggle\ 目录；首次使用编译脚本前需先运行 环境变量.bat 设置 ASE_API（用户级永久环境变量，重启命令行 / VS 后生效）。
第四章 · 配置详解

配置文件说明

插件启动时读取服务器目录下的 ArkApi\Plugins\DamageDisplayToggle\config.json（源码 Main.cpp 的 ReadConfig()）。

ShooterGame\Binaries\Win64\ArkApi\Plugins\DamageDisplayToggle\
├── DamageDisplayToggle.dll
├── DamageDisplayToggle.pdb
├── PluginInfo.json
├── config.json                        ← 插件配置
└── DamageDisplayToggle.db             ← SQLite 数据库（首次加载自动创建）
JSON 里逗号、引号一个都不能少。建议用带 JSON 校验的编辑器（如 VS Code）修改；改前先备份。文件编码为 UTF-8。修改后可在控制台 / RCON 执行 DamageDisplayToggle.Reload 热重载，无需重启服务器。

第四章 · 配置详解

ConsoleEncoding 控制台编码

什么意思：控制插件往服务器控制台输出文字时用的编码。不同版本 ArkApi 的服务器控制台编码不同（3.54 为 GBK/ANSI，3.55 为 UTF-8），编码不匹配时控制台中文会乱码。本插件输出前会按这个配置决定是否把 UTF-8 转成 GBK（Main.cpp 的 应用控制台编码配置，插件日志模块 h/日志.h 的自动输出系列同受其控制）。

兜底值：auto（配置缺失或值非法时都按 auto 处理，非法值会在控制台提示一行黄色警告）

{
  "ConsoleEncoding": "auto"
}

怎么修改：可选值共三个（大小写不限）：

取值效果
auto自动探测：控制台代码页为 936 时转 GBK 输出，否则按 UTF-8 原样输出。3.54 / 3.55 服务器都不用改配置，推荐保持默认
gbk强制输出前转 GBK（写 ansi 也可以）
utf8强制 UTF-8 原样输出（写 utf-8 也可以）
改完不用重启：控制台 / RCON 执行 DamageDisplayToggle.Reload 即可热生效（编码解析在每次读取配置时进行）。
第四章 · 配置详解

Sqlite 小节（数据库文件位置）

什么意思：插件用 SQLite 数据库记住每个玩家的开关状态，Sqlite.DbPath 决定数据库文件放哪。SQLite 是嵌入式数据库，整个库就是一个文件，无需安装任何数据库服务。

兜底值：空串 = 默认路径（配置缺失、小节缺失时同样用默认路径）

{
  "Sqlite": {
    "DbPath": ""
  }
}

怎么修改：把 DbPath 改成想要存放的文件完整路径即可，例如 D:/ARKData/DamageDisplayToggle.db（正斜杠 / 反斜杠均可）；留空或删除整个 Sqlite 小节都用默认路径。

项目说明
数据表PlayerDamageDisplay，两列：SteamId（玩家 SteamID，主键）、HideDamage（1 = 该玩家已关闭伤害显示，0 = 显示）
默认路径服务器运行目录/ArkApi/Plugins/DamageDisplayToggle/DamageDisplayToggle.db（首次启动自动建库建表）
生效时机DbPath 仅在插件加载（服务器启动）时读取一次，修改后需重启服务器生效，Reload 不会迁移或重开数据库
备份 / 迁移直接复制 .db 文件即可备份；换服务器时把文件放到对应路径即可保留全部玩家的设置
想让某位玩家恢复默认（重新显示伤害）或清空全部记录时，先停服或确保无写入，再用任意 SQLite 工具操作：DELETE FROM PlayerDamageDisplay WHERE SteamId = 玩家SteamID;（清空全部则去掉 WHERE 子句）。手工改库前请先备份 .db 文件。
第五章 · 命令用法详解

命令总表与改名

玩家命令在游戏内聊天框输入；服主命令在服务器控制台或 RCON 输入。

命令权限作用改名配置键
/开启伤害显示所有玩家（聊天）恢复显示该玩家自己的伤害数字ChatCommand.PlayerCommands.ShowDamage
/关闭伤害显示所有玩家（聊天）关闭该玩家自己的伤害数字显示ChatCommand.PlayerCommands.HideDamage
DamageDisplayToggle.Reload管理员（控制台 / RCON）重新读取 config.json，免重启刷新配置无（命令名由插件英文名决定）

怎么给玩家命令改名：修改 ChatCommand.PlayerCommands 里对应键的值即可，例如改成英文命令：

"PlayerCommands": {
  "ShowDamage": "/damageon",
  "HideDamage": "/damageoff"
}
改完命令文本后执行 DamageDisplayToggle.Reload：插件会自动卸载旧文本命令、挂上新文本命令，玩家立即用新命令（本插件的聊天命令热重载已做平滑迁移，无需重启）。若改坏了 JSON 本身，重载会整体失败、旧命令原样保留；若 JSON 合法但删掉了命令键，重挂时命令可能丢失——修正配置后再执行一次 Reload 或重启服务器即可恢复。
第五章 · 命令用法详解

DamageDisplayToggle.Reload 命令详解

作用：让插件重新读取 config.json（含气泡文案、命令文本、控制台编码），改完配置不想重启服务器时用它，立即生效。

DamageDisplayToggle.Reload
参数必填缺省值说明
无参数——本命令不带任何参数（源码 Main.cpp 的 ReloadConfig / ReloadConfigRcon）

示例：DamageDisplayToggle.Reload（插件立即重新读取配置并按新文本重挂玩家聊天命令）

反馈：成功时从游戏内控制台执行的服主会收到「配置已重载」气泡（Notification.ReloadSuccess）、RCON 返回 Reloaded config；配置有错时收到「配置重载失败」气泡（Notification.ReloadFailed）或 RCON 返回具体错误，同时错误详情写入服务器日志。只能在控制台 / RCON 使用，不是游戏内聊天命令。另外：Sqlite.DbPath 不参与热重载，修改它需要重启服务器。

第六章 · 常见问题

常见问题

插件加载失败，日志提示 Notification 缺少必需条目 / ChatCommand 缺少命令？
先试这个：这是配置不全的响亮失败。对照本教程第四章配置总表，把日志里点名的条目补进 config.json（注意每条气泡必须 Text / Scale / Time / Color 四字段齐全），再重启或 Reload。
玩家说命令没反应？
先试这个：确认玩家输入的是当前配置里的命令文本（你若改过 ChatCommand.PlayerCommands，以新文本为准）；再确认改完配置后执行过 DamageDisplayToggle.Reload；最后确认玩家是在游戏内聊天框输入且带 / 开头。
控制台中文乱码（方块/问号）？
先试这个：保持 ConsoleEncoding 为 auto（插件会按服务器控制台代码页自动选择编码）并执行 DamageDisplayToggle.Reload；仍乱码再按 ArkApi 版本显式指定——3.54 服务器设 gbk、3.55 服务器设 utf8。
插件没加载，控制台提示 Can't open config.json？
先试这个：检查 ArkApi\Plugins\DamageDisplayToggle\config.json 是否存在、文件名拼写是否正确；存在则用 JSON 校验工具检查格式（多逗号、缺引号都会导致解析失败）。
改了 config.json 但没生效？
先试这个：在控制台或 RCON 执行 DamageDisplayToggle.Reload 热重载；若提示重载失败说明新配置格式有错，按日志报错修正后重试。注意 Sqlite.DbPath 是例外——它只在服务器启动时读取，改动需重启。
想清空某个玩家 / 全部玩家的开关记录？
先试这个：用 SQLite 工具打开插件目录下的 DamageDisplayToggle.db，执行 DELETE FROM PlayerDamageDisplay WHERE SteamId = 玩家SteamID;（清空全部去掉 WHERE）。删掉的玩家回到默认的「显示伤害」。改库前先备份文件，操作前最好停服。
数据库文件在哪？怎么换位置？
先试这个：默认在 ArkApi\Plugins\DamageDisplayToggle\DamageDisplayToggle.db；要换位置就修改 Sqlite.DbPath 为新文件的完整路径并重启服务器（Reload 不迁移数据库）。备份直接复制该文件即可。
配置文件放哪里？
插件目录固定为 ShooterGame\Binaries\Win64\ArkApi\Plugins\DamageDisplayToggle\config.json，与 DamageDisplayToggle.dll 同目录。
怎么临时停用插件？
把插件目录下的 DamageDisplayToggle.dll 改名为 DamageDisplayToggle.dll.arkapi（ArkApi 不加载该后缀），重启服务器即可停用；改回 .dll 恢复。
编译脚本报错找不到 ArkApi？
先试这个：运行工程目录下的 环境变量.bat 设置 ASE_API 环境变量指向 ServerAPI 目录（默认探测 D:\ASE\ServerAPI），设置后重新打开命令行 / VS 再编译；并确认 ServerAPI 已运行其 build.bat 生成 ArkApi.lib。
